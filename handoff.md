## What it does
LAN-only web dashboard (Docker on Unraid) for tracking progress in the Topps Slam trading card game. The user creates a "set" when it is released, chooses which rarity levels/variations to chase, and logs cards as they are collected. The dashboard shows Active sets and Expired sets (muted, read-only), with progress bars, countdowns, and ntfy reminders. Used only on a 27" 1440p desktop monitor; no login, no mobile layout.

Game rules that drive the design: levels are Uncommon, Rare, Super Rare, Iconic, Legendary; levels can have variations (e.g. Rare Chrome Green); card counts per set are arbitrary; cards can be traded; every set has an end date (the game shows "days left", which is why long-term sets are entered that way); some sets drop one or more cards per day or per week that are only obtainable during that day/week. The user wants a drop to appear on the dashboard at 11:00 their time (when it goes live in the game).

## Stack
Node 20 + Express 4 (only dependency), vanilla HTML/CSS/JS front end (no build step), JSON file storage. Docker (`node:20-alpine`). Node's built-in `fetch` is used for ntfy and for the upscaler proxy (Node >= 18). The front end uses modern CSS/JS features: `zoom`, container query units (`cqw`), `Element.animate()` (Web Animations API), `matchMedia`. The user views it in desktop Firefox (earlier sessions) on Windows.

Second container (`upscaler/`, optional): `ubuntu:24.04` + distro `nodejs` (no npm dependencies) + `mesa-vulkan-drivers` (lavapipe software Vulkan, so no GPU needed) + the `realesrgan-ncnn-vulkan` v0.2.5.0 Linux release binary downloaded from GitHub at build time (models used: `realesr-animevideov3` x2/x3/x4 and `realesrgan-x4plus`). Free and offline at run time.

## Data model (`DATA_DIR/data.json`)
```
{ sets: [ { id, name, type: 'longterm'|'weekly'|'daily', startDate|null, endDate 'YYYY-MM-DD',
            endAt epoch-ms (long-term only; absent on long-term sets saved before 0.4.6; endDate is its local date in TZ),
            releaseDay 0-6|null (weekly), cover '/images/<uuid>.jpg'|'', createdAt,
            items: [ { id, level, variation ('' if none), total, owned } ],
            slots: [ { date } ],  // daily/weekly only: one per drop, built from startDate (+ releaseDay)
            perDrop 1-20 (daily/weekly: cards released per drop; absent on older sets = 1)
          } ],
  notified: { '<setId>:<date>:<release|ending>': true }  // pruned after 30 days
}
```
Long-term: the server stores `endAt` (epoch ms) = now + `daysLeft` days + `hoursLeft` hours at save time, and `endDate` = the `TZ` calendar date of `endAt` (used for sorting, display, pruning order and ntfy day counts); the form never sends a date. Long-term sets saved before 0.4.6 have only `endDate`. Daily/weekly: the user enters a start date (and release weekday for weekly) and `perDrop`; the number of drops is `ceil(largest item total / perDrop)` and `endDate` is derived (daily: last drop date; weekly: last drop + 6 days). Older records may still contain `got` on slots; it is ignored. A corrupt `data.json` is renamed to `data.json.corrupt-<ts>` on startup rather than overwritten. No data shape changes were made in 0.4.7-0.5.1 (grace period, drop time, card effects and the stack view are computed or browser-only).

**Browser-side storage (not in `data.json`):** `localStorage` key `slamStacked` (`'1'` = collapsed) holds the Collapse/Expand choice, per browser. Reads/writes are wrapped in try/catch.

## API
`GET /api/state` (returns `tz`, `ntfy: {configured, notifyTime}`, `enhance: true|false`, `sets`); `POST /api/sets`; `PUT /api/sets/:id`; `DELETE /api/sets/:id` (404 unknown, 403 if ended; also clears that set's `notified` keys and deletes its cover file unless another set still uses the same cover); `POST /api/sets/:id/items/:itemId` ({delta} or {value}); `POST /api/upload` (raw png/jpeg/webp body); `POST /api/ntfy/test`. Item route returns the updated set. Ended sets (including ones in the grace day) reject edits/progress with 403 (`locked()` in `server.js` still uses `D.isExpired`).

Set body for POST/PUT: `{ name, type, startDate, daysLeft, hoursLeft, keepEnd, perDrop, releaseDay, cover, items: [{ id, level, variation, total }] }`. `daysLeft`, `hoursLeft` and `keepEnd` are used only for `type: 'longterm'`: days 0-3650 and hours 0-23, a blank one counts as 0, both blank gives "Enter the time remaining", a zero total gives "Time remaining must be more than 0"; `keepEnd: true` on a PUT keeps the existing set's `endAt`/`endDate` untouched (the form sends it when the user didn't change days/hours); `startDate`, `perDrop` and `releaseDay` only for daily/weekly (`perDrop` omitted or empty = 1; outside 1-20 gives "Cards per drop must be between 1 and 20"). A client sending the old `endDate` field for a long-term set is ignored.

Enhance (proxied to the upscaler, 503 if `UPSCALER_URL` is unset, 502 if unreachable): `POST /api/enhance?model=fast|best&scale=2..4` (raw PNG/JPEG body, <= 12 MB) -> `{id}` (429 if the upscaler is busy, 400 for a bad image); `GET /api/enhance/:id` -> `{status: running|done|error, progress 0-100, error}`; `GET /api/enhance/:id/result` -> PNG; `DELETE /api/enhance/:id` cancels/discards. Upscaler's own API is the same under `/jobs` plus `/health`; finished jobs are dropped after 20 minutes.

## How components interact
The browser loads `/api/state` (refreshes every 60s and on tab focus, but not while the set form is open), renders everything client-side with `dates.js`, and posts small changes. The cover is cropped in the browser (canvas) and uploaded as a JPEG only when the set form is saved. The server's scheduler (every 60s) uses the same `dates.js` helpers to decide which ntfy messages are due. The server also prunes expired sets at startup and every 10 minutes.

`render()` in `app.js` rebuilds the whole Active and Expired innerHTML every time (after +/-, the 60s refresh, the Collapse/Expand toggle). So anything that lives on a card element (tilt CSS variables, `--i` stack index) must be re-applied at the end of `render()`; that is what `reapplyTilt()` and the stack code at the end of `render()` do.

Enhance flow: in the cropper, "Use crop" grabs the crop at native pixels; if enhancing is on (Off/Fast/Best buttons, default Fast, remembered per page load in `enhMode`) and the crop's long side is under 900px, the PNG is posted to `/api/enhance`, the dialog shows a progress bar (polls every 1.2s) with Cancel, then a before/after comparison with Use enhanced / Use original / Cancel. The chosen image is shrunk to <= 1400px JPEG (.92) and held until the set form is saved. Errors offer "Use original crop". Fast picks scale 2-4 so output is about 1000px; Best always runs 4x.

Long-term form flow: the form's **Days remaining** and **Hours remaining** inputs (`#f-days`, `#f-hours`, state `F.daysLeft`/`F.hoursLeft`) are sent as `daysLeft`/`hoursLeft`. When editing, they are pre-filled from `D.minutesLeft(set, now)` and the originals are remembered (`F.origDays`, `F.origHours`, `F.origType`); on save `keepEnd` is true only if an existing long-term set's two values are unchanged. Duplicate opens them blank.

## Key decisions / behavior

### Ending, grace day and expiry (0.4.6-0.4.7)
- `D.isExpired(set, today)` (unchanged since 0.4.6) means "has ended": `Date.now() >= endAt` when `endAt` exists, otherwise `today > endDate` (today in `TZ`). `minutesLeft` is `ceil((endAt - now)/60000)` for `endAt` sets.
- 0.4.7 added in `dates.js`: `endedAtMs(set, tz)` = `endAt`, or the start of the day after `endDate` in `tz` (computed by `startOfDayMs`, which iterates the zone offset); and `isArchived(set, tz)` = `Date.now() >= endedAtMs + 24h`. Ended but not archived = the **grace day**.
- `app.js` `render()`: Active = all non-archived sets, sorted ended-last (grace sets), then weekly-card-live-today first, then by `endDate`, then name; Expired = archived sets, newest `endDate` first. The stat tiles (Running, Need to finish, Completed, Ending <= 3 days) are computed from `live` = Active sets that have not ended, so grace sets are excluded. The section counts are the number of cards in each section (grace sets count toward Active).
- `app.js` `card(s, expired)`: the second argument means "has ended" (`D.isExpired`); inside, `grace = expired && !D.isArchived(s, state.tz)`. Classes: `expired` only when ended and archived; grace cards get `grace` plus `gdone` (all chased bars complete) or `gmiss`; the `complete` class is not applied to grace cards. Grace label: `Ended <m>m ago` / `Ended <h>h <m>m ago` / `Ended <1m ago`, from `Date.now() - endedAtMs`; it only updates when the dashboard re-renders (about once a minute). Archived expired cards keep `Ended <date>`.
- Styling (`style.css`): `.card.grace` has `opacity .88`, its direct children get `filter: grayscale(1)`, and an `::after` overlay uses `mix-blend-mode: color` with `rgba(95,140,110,.6)` (gdone, border `#4a6354`) or `rgba(150,85,92,.6)` (gmiss, border `#6e4f53`). The user viewed it in their browser and approved the look.
- Grace and expired sets are read-only (no +/-, no Edit button, server 403); Duplicate works.
- Auto-prune (0.4.2, changed in 0.4.7): `pruneExpired()` in `server.js` runs at startup and every 10 minutes. It selects `D.isArchived(s, TZ)` sets only (so grace-day sets are never pruned), keeps the newest `KEEP_EXPIRED` (default 15; sorted by `endDate` desc, then `createdAt` desc) and deletes the rest via `removeSets()` (also used by the delete route), which removes the sets, their `notified` keys, and cover files not used by any remaining set. Deletion is permanent.
- Expiry compares against the machine clock (`Date.now()`), so `endAt` sets do not depend on `TZ`; `TZ` only affects which calendar date `endDate` is and when daily/weekly sets end (midnight in `TZ`).

### Drop time (0.4.9)
- `dates.js` has `DROP_HOUR = 11`, a module variable `curTz` (default `'America/Phoenix'`), and helpers: `dropLive(today)` (true if `today` is not the current local date, or the current local hour >= `DROP_HOUR`), `dropDate(today)` (`today`, or the previous day while before the drop hour), `todaySlot(set, today)` (the slot dated `today`, only once the drop is live, else `undefined`). `released(set, today)` counts slots with `date <= dropDate(today)`, so `itemMissing` (and with it the "N missing" badge, the behind-row styling and the weekly ntfy "behind" check) lags by a day until 11:00. Exports: `todaySlot`, `DROP_HOUR`, `endedAtMs`, `isArchived`, plus the older helpers.
- **Hidden dependency:** `curTz` is set by the exported `nowParts(tz)`, which is a wrapper around the original (the original stays internal). Anything calling `released`/`itemMissing`/`todaySlot` relies on `D.nowParts(tz)` having been called earlier in the same process/page. The browser calls it at the top of `render()`, and the server calls it in `locked()`, `pruneExpired()` and `runNotifications()`. If a new code path uses these helpers before any `nowParts` call it silently uses America/Phoenix. The 11:00 rule applies to the real current date only (a `today` argument that is not the current local date counts as live).
- Not drop-time-aware on purpose: `remaining()` / `windowEnd()` ("X days/weeks remaining") and set end times still follow calendar days.
- `app.js` uses `D.todaySlot(s, now.date)` for `rel` (the card's "new card today" state) and in `render()` for `dropToday` (weekly sets with a live card sort first, before the endDate sort). `server.js` `runNotifications()` uses it for the weekly slot as of 0.5.2 (before that it used `s.slots.find(...)`), so the weekly "new card today" ntfy only goes out once the drop is live (11:00) and `NOTIFY_TIME` has passed.

### Card effects (0.5.0)
- CSS (`style.css`, right after `.card.urgent{...}.card.complete{...}`): every rule is scoped with `.card:not(.grace):not(.expired)` so grace-day and Expired cards stay flat (their grayscale/`mix-blend-mode` tint must not be disturbed). Live cards get `position:relative`, a `transform: perspective(900px) rotateX(var(--rx,0deg)) rotateY(var(--ry,0deg)) translateY(var(--lift,0px))`, a layered `box-shadow`, and a transition on `transform` (.15s). `:hover` sets `--lift:-5px` and a deeper shadow. A `::before` pseudo-element (z-index 3, `pointer-events:none`) draws a `radial-gradient` glare centred at `--mx/--my`, shown only on hover. A `@media (prefers-reduced-motion:reduce)` block removes the transform/transition and hides the glare.
- JS (`app.js`, just above the final `load()` call): one `pointermove` listener on `document` finds the `.card` under the pointer (skipped for grace/expired cards and for touch), computes the pointer's fraction across the card's own bounding rect (this stays correct under the grid's `zoom:.75`), and sets `--rx`, `--ry` (fraction x 10 degrees), `--mx`, `--my` on that card. State lives in `tilt` (`{id, rx, ry, mx, my}`); `dropTilt()` clears it when the pointer leaves a card or the page (`pointerleave` on `<html>`). `reapplyTilt()` is called at the end of `render()` because `render()` rebuilds the cards. Cards carry `data-id="${s.id}"` so the tilt can find the same card again after a re-render. `calm = matchMedia('(prefers-reduced-motion: reduce)')` is also used by the toggle animation.
- **Gotcha that cost a debugging round:** if Windows **Animation effects** is OFF (Settings > Accessibility > Visual effects), browsers report `prefers-reduced-motion: reduce` and the whole effect, plus the Collapse/Expand animation, is skipped. The user had it off at first; turning it on fixed it. Check `matchMedia('(prefers-reduced-motion: reduce)').matches` in the console first if "nothing happens".
- The glare strength is the `.16` in the `rgba(235,233,228,.16)` gradient; the tilt strength is the `* 10` in the `rx`/`ry` lines.
- Offered but not confirmed as applied: a stronger resting shadow (`inset 0 1px 0 rgba(235,233,228,.08)` light top edge plus a 1px dark outline) because black shadows are barely visible on the near-black page. Not known whether the user applied it.

### Collapse / Expand stacked view (0.5.1)
- Button `#stackToggle` in `index.html` (text "Collapse"/"Expand", set by `render()`). State `stacked` (module-level `let` near the top of `app.js`), loaded from `localStorage` key `slamStacked` and saved on each toggle.
- `render()` (end, before `reapplyTilt()`): toggles class `stack` on `#active`, sets `--n` (number of cards) on `#active` and `--i` (0-based index, in Active order) on each card. Only `#active` is ever stacked; `#expired` stays a grid.
- CSS (`style.css`, right after the dead `.card.release` rule): `#active.stack` becomes `display:flex; flex-direction:row; justify-content:center; align-items:flex-start; gap:0; padding:26px 0 8px; --peek:110px` and `container-type:inline-size`. Each card is `flex:none; width:420px; z-index:calc(var(--n) + 1 - var(--i))` so the first (soonest-ending) card is on top. All cards except the last get `margin-right: calc(min(var(--peek), (100cqw - 420px) / (var(--n) - 1)) - 420px)`: a negative margin so each next card peeks out by at most 110px, shrinking automatically when there are many sets so the stack fits the container width (`cqw` = container query units of `#active`). Hover: `z-index:500` brings a buried card to the front and `--lift:-14px` raises it (so +/- are usable on a hovered buried card). `.badges` gets `flex-direction:row-reverse` so the type badge is top-RIGHT and the status badges (N missing / NEW CARD TODAY / Complete) top-left; `.badge .xtra{display:none}` hides the long part of the type text.
- `card()` in `app.js` renders the type badge as `Weekly` / `Daily` / `Long-term` plus `<span class="xtra"> drops · Fridays</span>`; in the grid the pieces read "Weekly drops · Fridays" exactly as before, in the stack only the short type shows.
- Direction history: the first version put the top card on the right (row-reverse, like a fanned hand of playing cards); the user asked to flip it so the top card is on the LEFT, so it is now a plain `flex-direction:row` with `margin-right` overlaps. The flip also changed which edge of a buried card is visible: now the RIGHT edge (type badge, +/- column, bar ends); names are hidden until hover.
- Animation (FLIP, in the `#stackToggle` click handler): record each Active card's `getBoundingClientRect()` by `data-id`, flip `stacked`, call `render()`, then for each card `animate()` from `translate(dx, dy) scale(k)` (transform-origin 0 0) back to `none` over 450 ms with `cubic-bezier(.2,.8,.2,1)`. The deltas are divided by a constant `ZOOM = .75`, which **must match the `zoom` on `.grid`** in `style.css`. Skipped when `calm.matches` (reduced motion). The Expired section is not animated and the page below the Active section simply jumps when its height changes (user said that is fine for now; may want it animated later when Expired cards exist).

### Other behavior
- Progress counts unique cards per chased level/variation (no per-card tracking). Overall = completed bars / chased bars. Every set must chase at least one level.
- Daily/weekly sets: the drops ARE the cards of the chased level/variation (no separate drop bar, chips or "number of drops" field; the length is `ceil(largest item total / perDrop)`). Cards you should have by now = released drops x `perDrop` (capped at the item total, see `itemMissing`); if owned is lower a red "N missing" badge (sum across items; tooltip lists which) shows in the card's top-right corner (top-left while stacked) and the behind rows get a reddish label. The card shows "X weeks/days remaining" (drops whose availability window hasn't closed; daily window = that day, weekly = release day + 6) instead of an end date. Long-term cards show "Ends <date> · Xd Yh left".
- Start date is kept for daily/weekly so a set added late can be backdated to when the first card dropped.
- Release badges (0.4.8): for daily AND weekly sets (`timed`), when `todaySlot` exists the right-hand badge is red pulsing "NEW CARD TODAY" (class `badge rel`) while behind, or green "Collected today ✓" (class `badge ok`) when caught up (all `itemMissing` are 0). They show from 11:00 until midnight on the drop date. Only weekly sets jump to the front of Active; daily sets do not (they would always be first). The red release-day card border/glow was removed in 0.4.8 by deleting `rel && 'release'` from the card's class list; the `.card.release` rule in `style.css` is dead code (harmless).
- Look: portrait trading-card cards (`aspect-ratio: 5/7`, cover flexes to fill, card grows if many bars). The 25% size reduction is done with `zoom: .75` on `.grid`. Page background is a dark overlay over an inline-SVG diamond-plate tile (see `body` in `style.css`). The add/edit set modal is scaled with `#modal .dialog{zoom:.75; max-height:calc(92vh / .75)}` (the cropper dialog is intentionally not scaled). Cropper default is 1:1. The plain (non-enhanced) crop is capped at 1400px on its longest side. A card still gets a red "urgent" border when under 24 hours remain (not for ended sets).
- ntfy: weekly -> on a release day once the drop is live (11:00) and `NOTIFY_TIME` has passed, if behind on any chased item and set incomplete; long-term -> daily from 5 days before the end date through the end date listing missing cards, skipped if complete or already ended; daily -> none. Sent once per day after `NOTIFY_TIME`; only logged as sent if ntfy accepted it. Uses ntfy's JSON publish API.
- Level colors: Uncommon green, Rare blue, Super Rare purple, Iconic red, Legendary gold. Completed bars use a different, muted green with a checkmark.
- Editing: item ids are preserved so progress survives edits; removing a level/variation deletes its progress. Saving a daily/weekly set recalculates slots and `endDate`; saving a long-term set with changed days/hours restarts the countdown from now.
- Active sets can be deleted from the Edit dialog (button on the left of the dialog actions; first click turns it into "Click again to delete for good", second click deletes). Card footer Edit/Duplicate are icon-only (inline SVGs in `ICONS` in `app.js`).

## Known limitations / unfinished
- `pruneExpired()` in `server.js` has an unused `today` variable (harmless).
- Collapsed stack: status badges (N missing, NEW CARD TODAY, Complete) are top-left, so hidden on buried cards until hover; names are hidden on buried cards; stacked cards are a fixed 420 px wide (in the zoomed coordinate space); the Expired section and the page below do not animate; the `ZOOM = .75` constant in the toggle handler duplicates the CSS `zoom` on `.grid` (change both together).
- Card effects are disabled when the OS reports reduced motion (see Card effects), which can look like a bug.
- `DROP_HOUR` is one hardcoded value for every set and is not configurable without editing `dates.js` and rebuilding.
- `curTz` is module-level state set as a side effect of `D.nowParts` (see Drop time). It works today but is fragile if new code skips `nowParts`.
- "X days/weeks remaining" and set end times are calendar-day based, not drop-time based. For example, early in the morning before 11:00 the current day still counts as remaining.
- Cards per drop is one value for the whole set. If different levels in one daily/weekly set release at different rates, the numbers will be off for the others. No separate "number of drops" field.
- Weekly notification only knows if the user is behind overall, not specifically whether this week's card was collected.
- Covers cropped before 0.3.0 (5:2) are center-cropped on the portrait cards; re-crop via Edit > Replace.
- Replaced covers are not deleted from `images/` (orphans accumulate; auto-prune only removes covers of pruned sets).
- Ended sets (grace and expired) cannot be edited or manually deleted; a mistyped end date can only be fixed by duplicating (before the set ends or while it is still in the Expired top 15).
- Grace-day label updates only on the 60s refresh; the refresh is paused while the set form is open.
- Enhance: one job at a time; abandoning the page mid-job leaves it running until it finishes or times out; Best is slow on CPU; crops >= 900px skip enhancing; no GPU passthrough support configured.
- No per-card tracking, no auth, no snooze/quiet hours. `.card.release` in `style.css` is unused. `package.json` version is stale (0.1.0).

## Modifying safely
- Keep rule logic (expiry, grace/archived, drop timing, drops remaining/missing, progress) in `public/dates.js` so server notifications and the UI stay consistent. Use `D.todaySlot` (not `slots.find(date === today)`) anywhere you ask "is there a live drop today"; use `D.isArchived` for "is it in the Expired section" and `D.isExpired` for "has it ended (read-only)".
- Make sure `D.nowParts(tz)` runs before using `released` / `itemMissing` / `todaySlot` in any new code path.
- Preserve item `id`s when editing sets (`cleanSet` matches by id) or progress is lost.
- Don't change the `data.json` shape without a migration in `load()`; the user's data lives there.
- Never put real secrets (ntfy topic/token) in committed files; they belong in `.env`. Keep `.env` in `.gitignore` and `.dockerignore`, and keep `.env.example` blank.
- The upscaler must run with explicit tiling (`-t`, set per model in `upscaler/server.js`); an early untiled run hung for minutes.
- The upscaler container must not be published to the LAN; only the app talks to it.
- All writes go through `save()` (atomic rename).
- Front end has no build step; escape user text with `esc()` before putting it in HTML.
- The grace-day tint relies on `mix-blend-mode: color` over a stacking context created by the card's `opacity`; don't remove the opacity or the `position: relative` without re-checking it in the browser.
- `render()` replaces every card element. Anything stored on a card element must be re-applied at the end of `render()` (tilt vars via `reapplyTilt()`, the stack's `--n`/`--i`), and the stack/tilt CSS depends on the `data-id` attribute and the `grace`/`expired` classes on `<article class="card ...">`.
- Keep the card effect CSS scoped to `.card:not(.grace):not(.expired)`; applying a `transform` to grace cards would break the tint's stacking context.
- If you change the `zoom` on `.grid`, change `ZOOM` in the Collapse/Expand handler in `app.js` too, and re-check the 420 px stacked card width in `style.css`.
- In the stack, `#active.stack ...` selectors use the id on purpose so they beat the class-only rules (for example the hover `--lift` for live cards).
